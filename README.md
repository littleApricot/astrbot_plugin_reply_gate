# 回复判断

普通消息合并成批，统一交给百炼 `decision-model-preview` 判断是否接话；@ 立即接管尚未开始判断的消息，跳过合并等待和判断。正式回复沿用 AstrBot 的回复模型、人格和工具，并在每次模型调用前读取最新有效历史。

适配 AstrBot `>=4.29.1,<4.30.0`，验证目标为 4.29.1。

## 安装和更新

在 AstrBot 插件市场添加已有共享源：

```text
https://raw.githubusercontent.com/littleApricot/astrbot_plugin_reply_gate/main/plugins.json
```

安装“回复判断”，后续通过已安装插件页检查更新。仓库为 [littleApricot/astrbot_plugin_reply_gate](https://github.com/littleApricot/astrbot_plugin_reply_gate)。共享源也提供记忆与记事本、群聊表情图库和 LCM。配套使用本次功能时，更新回复判断 v0.8.1、记忆 v0.5.0、图库 v0.5.0、LCM v0.6.0。

本地密钥、地址、预算、活跃度、合并时间和已有自定义提示词在更新时保留。只替换插件程序文件，运行数据留在 AstrBot 数据目录。

## 配置

| 配置键 | 默认值 | 用途 |
| --- | --- | --- |
| `enabled` | `true` | 启用回复判断 |
| `bailian_api_url` | 空 | 百炼参考代码中的完整 `/compatible-mode/v1/systemone` 请求地址 |
| `bailian_api_key` | 空 | 参考代码的 Authorization 完整值；示例含 Bearer 时一并填写 |
| `failure_default_reply` | `true` | 判断失败后进入正式回复；关闭则保持沉默 |
| `reply_activity` | `0.5` | 回复倾向，范围 0～1，越高越容易回复 |
| `merge_idle_seconds` | `1` | 普通消息收集的安静等待秒数，范围 0～60 |
| `merge_max_wait_seconds` | `3` | 普通批次的最长收集秒数，范围 0～60 |
| `context_budget` | `60000` | 判断总输入预算，范围 2048～62000，按 UTF-8 字节保守估算 |
| `timeout_seconds` | `30` | 判断调用超时秒数 |
| `decision_instructions` | 完整默认规则 | 唯一判断提示词，包含接话规则、概率含义和输出提醒 |

首次填入匹配的百炼空间地址与密钥，并确认目标会话的 AI、正式回复模型及本插件已启用。QQ 平台必须实际下发普通群消息，插件才能判断。Authorization 原样发送，不自动添加前缀。配置输入框遮罩不改变 AstrBot 本地配置文件的存储方式。

接口缺失、超时、非法结果或记忆超预算时，按失败配置处理。取得有效结果时按结果执行。@ 绕过判断及其预算和失败策略；生成与发送仍需要回复模型及平台正常工作。原生管理命令沿用原处理流程。

## 判断输入和预算

判断请求的数据区分为：

- `state.memory`：当前人格与完整常驻记忆。与记忆插件配合时，使用其本轮渲染结果；单独使用时读取选中的原生人格。
- `state.messages`：最新有效历史的近期部分，以及本批待回复消息。保留用户、助手和允许进入历史的工具调用与结果。
- `state.pending_count`：尾部属于本批的用户消息数，裁剪后按实际保留数量计算。

工具定义、工具使用说明、记事本目录、表情推荐等本轮辅助资料不加入判断输入。正常历史中已经允许保存的工具结果仍属于历史资料。当前消息保留正文、图片等媒体和引用；发送人作为数据附带。

图片统一转为 `[图片]`。图库能精确匹配现有文件或已收集引用时，附带当前名称与描述；没有匹配或尚未识别时保留占位。查询只读取已保存资料。正式回复与原始历史继续保留图片。

预算包含记忆、完整判断提示词、JSON 结构和 1024 字节预留，属于保守估算，不是精确 token 数或计费量。优先完整保留记忆和判断提示词，再裁掉最老完整对话轮次，工具调用及结果随所在轮次一起裁剪。全部历史仍不够时，保留当前消息末尾；受保护的记忆本身装不下则报 `protected_context_too_large`，按失败策略处理。

裁剪只针对判断副本，不修改共享历史或正式回复窗口。有效历史也可能已经由 LCM 压缩，判断使用其最新表示。

`decision_instructions` 是唯一提交给决策问题的提示词，代码不另加接话规则或隐藏的结果提醒。API 固定的 `model`、`type=noul`、问题名 `should_reply` 及 0～1 数值校验属于接口协议。清空配置时显示并保存默认提示词；非空自定义值保留，可完整编辑。

## 合并、@ 与并行

普通消息在同一平台会话内合成一批，只判断和计分一次。新消息延长安静等待，但不超过最长收集时间；两个时间都可设为 0。每批独立处理，插件不限制并行批次数；提供商自身限制仍然适用。

@ 到来时，立即收走同会话所有尚未进入判断准备的消息，按原顺序组成一轮，以 @ 消息作为本轮回复入口。待处理消息在进入上下文准备时原子领取；已经领取的批次，无论正在判断、生成还是执行工具，都继续运行。@ 后新到的普通消息进入新的收集批次。旧批次被接管后停止自身回复路径，每条原消息只归属一轮。

用户消息按原顺序、发送者、时区时间、图片和引用加入本轮。原生群上下文中重复的本批记录去重。临时附件保留到所属批次结束；准备失败时停止本轮并记录错误类型。合并队列只在内存中，重载会取消未处理批次；持久历史继续保留。

各批完成即发送，不按开始次序排队；QQ 分条发送可能交错。每次模型调用前读取最新共享历史，因此前一批已完成的回复、历史清理和已发布摘要会进入后续调用。已经发出的请求保留发送时的输入。

本轮输入与尚未结束的工具过程作为本轮私有部分保留。完成后只合并本轮输出，保留并行更新；当轮专用记录按原生保存标记及图库历史处理规则清理。LCM v0.6.0 负责压缩后的有效历史及工具后调用刷新；未启用 LCM 时读取原生会话历史。插件只短暂锁定历史读写，不锁住整个生成过程。

## 活跃度与积累

| 活跃度 | 普通消息行为 |
| --- | --- |
| 0 | 保持沉默，跳过判断；消息仍保存 |
| 0～1 之间 | 每批取得分数后更新积累 |
| 1 | 直接进入正式回复，跳过判断 |

对中间档位 `a` 和模型分数 `p`，计算：

```text
增减量 = ln(p / (1-p)) + ln(a / (1-a))
触发前计算值 = max(0, 原有积累 + 增减量)
本次增减量 > 0 且计算值 >= 1：回复并清零
否则保存计算值
```

保存的积累始终满足 `0 <= 值 < 1`。低分最多扣到 0；触发后多余部分一并清空。日志中的触发前计算值可以超过 1，剩余值为 0。模型精确返回 0 时沉默并清零，返回 1 时通过并清零；活跃度端点规则优先。

例如活跃度 0.5 时，连续三批分数 0.6 会在第三批触发；从零开始的 0.7 不触发。活跃度 0.6 时，连续两批 0.6 在第二批触发。

积累按平台会话和当前对话 ID 隔离。重载、切换对话、改变活跃度后重新开始；@ 和失败放行清零。有效结果按返回次序更新，失败拦截不计分。放行后正式回复失败不退还积累。

## 日志和验证

日志记录批大小、等待时间、概率、积累变化、剩余值、是否回复和裁剪数量。失败以中文显示回退回复或沉默、错误类型与耗时，同类警告最多每分钟一次；不记录密钥、完整请求或聊天原文。

在 AstrBot Python 环境下运行：

```sh
PYTHONPATH=/path/to/AstrBot python -m pytest tests -q
```

确定性检查使用 AstrBot 原生消息分发、工具循环、历史保存和隔离的本地 HTTP 服务，覆盖图片占位、完整记忆与预算、唯一提示词、@ 接管边界、并行保存、判断后刷新、失败策略、积累和更新安装。测试不调用真实模型或 QQ；模型的语义判断质量、提供商并发和真实发送耗时仍需运行中观察。

## 发布

修改版本及更新记录，运行 `python scripts/prepare_release.py`，提交后创建同名版本标签和 Release，再更新共享源及 MD5。安装包使用源中固定版本的 ZIP。发布前验证源条目、校验和与包内版本一致。
