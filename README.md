# 回复判断

给 AstrBot 增加一个开口前的判断：**用户 @ 机器人时直接进入回复流程；含图片的普通消息用当前回复模型结合完整上下文判断；纯文字消息交给百炼 `decision-model-preview` 读取近期上下文判断。** 仅 @ 而没有正文时也进入正式回复流程，结合原会话上下文接话。正式回复继续使用 AstrBot 的完整请求、模型、人格和工具。

适配 AstrBot 4.29.x，当前本地验证目标为 4.29.1。百炼接口地址和密钥保存在 AstrBot 本地配置中。

## 安装和在线更新

仓库：[littleApricot/astrbot_plugin_reply_gate](https://github.com/littleApricot/astrbot_plugin_reply_gate)。

在 AstrBot 插件市场的“添加插件源”中填入：

```text
https://raw.githubusercontent.com/littleApricot/astrbot_plugin_reply_gate/main/plugins.json
```

添加后从该源安装“回复判断”。以后发布新版本，在已安装插件页面检查更新并点击更新即可。

同一个源还包含“群聊表情图库”和“自维护提示词”，可一起安装和更新。

如果此前通过 ZIP 安装了 v0.2.x，添加该源后从源中安装“回复判断”，AstrBot 会按插件名称替换旧版并绑定更新来源。首次升级后填写“百炼决策 API 地址”。已有百炼密钥、阈值、判断预算和自定义规则沿用原配置；“是否回复的判断规则”留空时使用内置规则。

## 首次配置

1. 打开 **回复判断 → 配置**，将“百炼决策 API 地址”填写为百炼控制台参考代码中的完整请求地址。地址包含自己的业务空间域名，路径以 `/compatible-mode/v1/systemone` 结尾，业务空间需要与密钥匹配。
2. 将“百炼 API Key / Authorization”填写为对应参考代码中 `Authorization` 的完整值。示例为 `Authorization: $DASHSCOPE_API_KEY` 时填写变量对应的值；示例为 `Authorization: Bearer $DASHSCOPE_API_KEY` 时填写 `Bearer ` 加密钥。插件原样发送该字段。
3. 保存配置。输入框默认遮罩，配置文件仍按 AstrBot 的方式保存在本机，后续插件更新继续使用这些本地配置。
4. 确认目标会话启用了本插件，AstrBot 的 AI 和正式回复模型也已启用。QQ 群需要在机器人设置中允许接收群内普通消息，否则插件只能处理平台实际下发的消息。
5. “判断上下文预算（UTF-8 字节估算）”新安装默认 60,000，升级时沿用原预算。该值只限制判断输入。初始回复阈值为 0.5，提高后会减少插话，可根据实际效果调整。

文字判断的接口地址或 Key 留空、判断接口超时、服务错误或结果无效时，自动放行给正式回复流程，原因写入插件日志。只有取得有效的不回复结论时才拦截。文字判断默认超时 30 秒，升级后已保存的超时值仍由本地配置决定。含图判断使用现有回复模型的配置；@ 消息直接走正式回复流程。这里的“直接回复”指跳过判断，发送仍依赖原回复模型、平台连接、会话权限等运行条件。AstrBot 原有管理命令继续执行。

## 判断窗口与正式回复

插件在 AstrBot 完成请求组装后，检查当前消息是否包含图片。含图时额外调用当前会话的回复模型，提供完整人格、记忆、历史对话和当前图片，只取得是否回复的布尔判断；判断调用不执行聊天工具，不发送聊天消息，也不写入历史。该路径使用原请求的模型覆盖设置，跳过百炼接口、文字预算和概率阈值，默认超时 30 秒。

视觉判断使用独立的顶层判断协议，将原人格、记忆和工具说明完整放在参考资料区，要求只提交 `should_reply` 布尔值。使用 OpenAI 兼容适配器连接 DeepSeek 官方端点 `api.deepseek.com` 时，判断调用关闭思考，强制返回唯一的 `submit_reply_decision` 函数及布尔参数。该函数只定义结果格式，没有执行处理器，不开放原聊天工具；收到结果后直接读取参数并结束判断。此方式替代了在完整聊天窗口下返回过空白正文的 JSON 模式。接口需要支持指定函数的工具选择，见 [DeepSeek Chat Completions 文档](https://api-docs.deepseek.com/api/create-chat-completion/)。

其他 OpenAI 兼容端点通过局部配置副本启用 `response_format={"type":"json_object"}`，需要接口支持此模式；非 OpenAI 适配器通过提示词请求 JSON。所有路径均保留共享提供商配置和正式回复请求。

函数结果必须恰好包含一次 `submit_reply_decision`，参数仅含布尔字段 `should_reply`；其他函数、多个调用或缺失调用记录为 `invalid_vision_decision`，错误字段或类型记录为 `invalid_vision_schema`。JSON 路径接受完整对象和完整代码围栏；空正文、非 JSON 正文分别记录为 `empty_vision_decision`、`invalid_vision_json`。普通工具调用文本不被当成回复判断。

纯文字时，从人格、系统指令、已注入的记忆、历史对话和当前用户消息中复制一份判断输入，并按预算保留最近一段。两条路径都保留正式回复的原始请求，窗口长度、轮次限制和压缩策略由 AstrBot 及回复模型原有配置管理。是否回复的判断规则只发给判断调用。

判断输入的裁剪顺序：

1. 删除最老的完整对话轮次，工具调用和结果一起删除。
2. 删除 AstrBot 注入的积压群聊记录中最老的消息。
3. 仍超长时，保留当前用户消息的末尾。人格、系统指令和当前轮已注入的记忆等额外内容保留。

人格、记忆等保留内容自身已超过预算时，判断无法执行，自动放行给正式回复流程，日志显示 `protected_context_too_large`；可调小这些注入内容来恢复判断。@ 消息跳过判断及其上下文预算。

“判断上下文预算（UTF-8 字节估算）”默认 60,000，上限 62,000，低于百炼文档中的 65,536 Token 窗口。文本以 UTF-8 字节作为保守的 token 上界估算，另外计入请求结构和指令预留空间，**不是精确分词计数，也不是正式回复的上下文上限**。中文通常会比模型真实窗口更早触发裁剪，以减少服务端超限的可能。

明确判断不回复时，插件保留已有会话历史，并追加完整的当前用户消息；临时注入的人格、记忆等内容仍按 AstrBot 的临时标记过滤。判断失败放行及正常通过时，由 AstrBot 执行正式回复并保存历史及新回复，插件不提前追加一份消息。判断窗口的裁剪只存在于该次判断请求中。

v0.3.1 修复了旧版将判断窗口写回正式请求和历史的问题。已经被旧版覆盖的历史需要从原始消息记录或备份另行恢复，升级本身不能重建它们。

## 图片、动图与语音

当前消息或当前轮注入内容包含实际图片时，使用当前回复模型进行视觉判断。该模型需要支持图片输入；缺少模型、模型明确不支持视觉、超时或返回无效判断时自动放行。日志显示 `source=reply_model_vision full_context=True`。支持的图片和动图格式仍取决于回复模型自身的接口。

百炼这款模型仅支持文字。当前消息只有原始音频等非文字内容时，文字判断无法执行，自动放行，日志显示 `unsupported_media`；@ 直接交给原回复流程。已由 AstrBot 转写成文字的语音可以参与判断。

后续收到纯文字消息时，判断输入会移除历史中无法处理的媒体轮次及其更早轮次，保留最近的文字对话。正式回复和已保存的历史继续保留原有媒体轮次。

## 配置参考

| 配置 | 默认值 | 用途 |
| --- | --- | --- |
| 启用回复判断 | 开启 | 在当前启用本插件的会话中接管普通消息的回复选择 |
| 百炼决策 API 地址 | 空 | 自己业务空间的完整决策接口地址 |
| 百炼 API Key / Authorization | 空 | 用户自行填写控制台示例中 Authorization 的完整值 |
| 回复概率阈值 | 0.5 | `should_reply.noul` 达到阈值才回复；概率不是回复次数的随机抽样比例 |
| 判断上下文预算（UTF-8 字节估算） | 60,000 | 只限制判断输入，包括文本、判断指令和预留空间 |
| 判断超时秒数 | 30 | 文字判断超时后自动放行 |
| 含图消息判断超时秒数 | 30 | 使用回复模型进行完整上下文视觉判断的超时 |
| 是否回复的判断规则 | 空 | 空值使用内置规则，可在页面编辑 |

内置规则结合人格、对话对象、话题和最近互动判断此刻是否适合接话。回应问候、确认在线、接住玩笑、表达情绪和闲聊互动，本身就是合理的回复目的。用户向机器人打招呼、呼唤、询问是否在线、试探是否有反应、追问、邀请互动或调侃机器人时倾向回复；短句、口语、玩笑和寒暄都可以构成完整的互动。对正在参与的对话和适合机器人接上的话题，也可以回复。其他人明确互聊且与机器人无关、单纯重复刷屏、话题结束或机器人刚表达过相同内容时倾向沉默。这些规则和阈值是可调整的初始设置，群聊中的判断效果需要用实际样例检验。

插件日志记录判断概率、是否回复和判断输入的裁剪数量；失败放行记录 `Reply gate failed open`、判断来源、耗时、超时上限和安全错误代码，不记录 API Key、完整请求、聊天原文或接口响应正文。回复模型的 HTTP 错误记录为 `provider_http_状态码`，便于区分接口故障与无效判断。百炼判断接口不自动重试；图片判断沿用 AstrBot 提供商适配器的错误处理机制，整体受含图判断超时限制。

## 本地验证

进入本插件目录，在 AstrBot 的 Python 环境中执行。将 `ASTRBOT_SOURCE` 改为自己的 AstrBot 源码目录；测试使用独立数据目录：

```bash
ASTRBOT_SOURCE=/path/to/AstrBot
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH="$ASTRBOT_SOURCE:$PWD/.." \
  ASTRBOT_ROOT=/tmp/astrbot-reply-gate-test \
  "$ASTRBOT_SOURCE/.venv/bin/python" -m pytest tests -q
```

测试使用构造的聊天、AstrBot 请求与运行器及历史保存代码、隔离的本地模拟 HTTP 接口和记录输入的回复模型，检查 @ 绕过、允许与拒绝、失败自动放行、文字窗口裁剪、正式回复保留完整请求，以及正常回复、沉默和失败放行时的历史保存。含图场景检查完整历史、人格、记忆和图片进入回复模型判断，跳过百炼和文字预算；使用真实 OpenAI 适配器与模拟 SDK 返回检查 DeepSeek 的指定函数与关闭思考参数、其他端点的 JSON 模式、共享配置不变和严格布尔解析。明确拒绝时保持沉默，判断无效或超时时使用原始完整请求回复；停止任务时的取消信号正常传播。更新测试通过本地插件源下载 ZIP，在临时目录替换旧插件，并检查配置保留和源缓存刷新。这些检查不覆盖真实模型鉴权、中文接话效果、QQ 发消息或远程发布后的安装流程。

接口参考：[百炼决策模型 API](https://help.aliyun.com/zh/model-studio/decision-model-api)、[模型能力、上下文和限流](https://help.aliyun.com/zh/model-studio/decision-model-preview)。

## 发布新版本

1. 修改代码和 `metadata.yaml` 中的版本号，并更新 `CHANGELOG.md`。
2. 在 AstrBot 的 Python 环境中执行 `python scripts/prepare_release.py`，同步生成 `plugins.json` 和 `plugins-md5.json`。
3. 提交代码，创建与版本号相同的 Git 标签，例如 `v0.3.0`，将提交和标签一起推送到仓库。
4. 插件源读取 `main` 分支的列表；安装和更新下载列表中指定标签的 ZIP。确认 GitHub 上该标签的 ZIP 可以下载后，再在 AstrBot 中检查更新。

插件源列表、版本号和 MD5 一起更新，避免命中旧的源缓存。发布内容只包含代码、说明和源索引；运行时配置保存在 AstrBot 的插件配置目录中。
