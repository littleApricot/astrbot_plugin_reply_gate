# 回复判断

给 AstrBot 增加一个开口前的判断：**用户 @ 机器人时直接进入回复流程；其他用户消息先交给阿里云百炼的 `decision-model-preview`，达到阈值后才回复。** 正式回复继续使用 AstrBot 中配置的模型、人格和工具。

适配 AstrBot 4.29.x，当前本地验证目标为 4.29.1。百炼接口地址和密钥保存在 AstrBot 本地配置中。

## 安装和在线更新

仓库：[littleApricot/astrbot_plugin_reply_gate](https://github.com/littleApricot/astrbot_plugin_reply_gate)。

在 AstrBot 插件市场的“添加插件源”中填入：

```text
https://raw.githubusercontent.com/littleApricot/astrbot_plugin_reply_gate/main/plugins.json
```

添加后从该源安装“回复判断”。以后发布新版本，在已安装插件页面检查更新并点击更新即可。

如果此前通过 ZIP 安装了 v0.2.x，先上传一次 v0.3.0 的 ZIP 并重载，再将该插件的更新来源绑定到这个源，或绑定到上述仓库。首次升级后填写“百炼决策 API 地址”。已有百炼密钥、阈值和自定义规则沿用原配置；“是否回复的判断规则”留空时使用内置规则。

## 首次配置

1. 打开 **回复判断 → 配置**，将“百炼决策 API 地址”填写为百炼控制台参考代码中的完整请求地址。地址包含自己的业务空间域名，路径以 `/compatible-mode/v1/systemone` 结尾，业务空间需要与密钥匹配。
2. 将“百炼 API Key / Authorization”填写为对应参考代码中 `Authorization` 的完整值。示例为 `Authorization: $DASHSCOPE_API_KEY` 时填写变量对应的值；示例为 `Authorization: Bearer $DASHSCOPE_API_KEY` 时填写 `Bearer ` 加密钥。插件原样发送该字段。
3. 保存配置。输入框默认遮罩，配置文件仍按 AstrBot 的方式保存在本机，后续插件更新继续使用这些本地配置。
4. 确认目标会话启用了本插件，AstrBot 的 AI 和正式回复模型也已启用。QQ 群需要在机器人设置中允许接收群内普通消息，否则插件只能处理平台实际下发的消息。
5. “共享上下文预算”新安装默认 60,000，升级时原来保存的值可能继续保留。初始回复阈值为 0.5，提高后会减少插话，可根据实际效果调整。

接口地址或 Key 留空、接口超时、服务错误或结果无效时，普通消息保持沉默，原因写入插件日志；@ 消息直接走正式回复流程。这里的“直接回复”指跳过判断，发送仍依赖原回复模型、平台连接、会话权限等运行条件。AstrBot 原有管理命令继续执行。

## 判断和回复共用什么

插件在 AstrBot 完成请求组装后读取人格、系统指令、已注入的记忆、历史对话和当前用户消息。裁剪完成后，一份交给判断接口，另一份通过同一个请求对象交给正式回复模型。是否回复的判断规则只发给判断模型；后续工具调用取得的新信息属于正式回复执行过程。

裁剪顺序：

1. 删除最老的完整对话轮次，工具调用和结果一起删除。
2. 删除 AstrBot 注入的积压群聊记录中最老的消息。
3. 仍超长时，保留当前用户消息的末尾。人格、系统指令和当前轮已注入的记忆等额外内容保留。

人格、记忆等保留内容自身已超过预算时，该条普通消息保持沉默，日志显示 `protected_context_too_large`，需要调小这些注入内容。@ 消息跳过判断及其上下文预算。

“共享上下文预算”默认 60,000，上限 62,000，低于百炼文档中的 65,536 Token 窗口。文本以 UTF-8 字节作为保守的 token 上界估算，另外计入请求结构和指令预留空间，**不是精确分词计数**。中文通常会比模型真实窗口更早触发裁剪，以减少服务端超限的可能。

未回复的用户消息也保留到 AstrBot 当前会话历史，因此下一次判断能看到之前没有接话的内容。这会延续原会话的持久化方式；裁剪后的会话历史随着后续处理保存。

## 图片和语音

百炼这款模型目前仅支持文字。当前消息或当前轮注入内容包含图片、原始音频等内容时，普通消息保持沉默，并记录 `unsupported_media`；@ 仍直接交给原回复流程。已由 AstrBot 转写成文字的语音可以参与判断。

后续收到纯文字消息时，插件会按从旧到新的顺序移除历史中无法处理的媒体轮次及其更早轮次，再将同一份剩余上下文用于判断和回复。图片内容不会被替换成占位文字后继续判断。

## 配置参考

| 配置 | 默认值 | 用途 |
| --- | --- | --- |
| 启用回复判断 | 开启 | 在当前启用本插件的会话中接管普通消息的回复选择 |
| 百炼决策 API 地址 | 空 | 自己业务空间的完整决策接口地址 |
| 百炼 API Key / Authorization | 空 | 用户自行填写控制台示例中 Authorization 的完整值 |
| 回复概率阈值 | 0.5 | `should_reply.noul` 达到阈值才回复；概率不是回复次数的随机抽样比例 |
| 共享上下文预算 | 60,000 | 包括文本、判断指令和预留空间的保守预算 |
| 判断超时秒数 | 8 | 超时后普通消息保持沉默 |
| 是否回复的判断规则 | 空 | 空值使用内置规则，可在页面编辑 |

内置规则结合人格、对话对象、话题和最近互动判断此刻是否适合接话。回应问候、确认在线、接住玩笑、表达情绪和闲聊互动，本身就是合理的回复目的。用户向机器人打招呼、呼唤、询问是否在线、试探是否有反应、追问、邀请互动或调侃机器人时倾向回复；短句、口语、玩笑和寒暄都可以构成完整的互动。对正在参与的对话和适合机器人接上的话题，也可以回复。其他人明确互聊且与机器人无关、单纯重复刷屏、话题结束或机器人刚表达过相同内容时倾向沉默。这些规则和阈值是可调整的初始设置，群聊中的判断效果需要用实际样例检验。

插件日志记录判断概率、是否回复和裁剪数量，不记录 API Key、完整请求、聊天原文或接口响应正文。判断接口不自动重试，避免一条消息反复付费和排队。

## 本地验证

进入本插件目录，在 AstrBot 的 Python 环境中执行。将 `ASTRBOT_SOURCE` 改为自己的 AstrBot 源码目录；测试使用独立数据目录：

```bash
ASTRBOT_SOURCE=/path/to/AstrBot
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH="$ASTRBOT_SOURCE:$PWD/.." \
  ASTRBOT_ROOT=/tmp/astrbot-reply-gate-test \
  "$ASTRBOT_SOURCE/.venv/bin/python" -m pytest tests -q
```

测试使用构造的聊天、AstrBot 请求与运行器代码、隔离的本地模拟 HTTP 接口和记录输入的回复模型，检查 @ 绕过、允许与拒绝、错误处理、上下文一致、旧消息裁剪、媒体处理与未回复消息保留；更新测试通过本地插件源下载 ZIP，在临时目录替换旧插件，并检查配置保留和源缓存刷新。这些检查不覆盖百炼真实鉴权、中文接话效果、QQ 发消息或远程发布后的安装流程。

接口参考：[百炼决策模型 API](https://help.aliyun.com/zh/model-studio/decision-model-api)、[模型能力、上下文和限流](https://help.aliyun.com/zh/model-studio/decision-model-preview)。

## 发布新版本

1. 修改代码和 `metadata.yaml` 中的版本号，并更新 `CHANGELOG.md`。
2. 在 AstrBot 的 Python 环境中执行 `python scripts/prepare_release.py`，同步生成 `plugins.json` 和 `plugins-md5.json`。
3. 提交代码，创建与版本号相同的 Git 标签，例如 `v0.3.0`，将提交和标签一起推送到仓库。
4. 插件源读取 `main` 分支的列表；安装和更新下载列表中指定标签的 ZIP。确认 GitHub 上该标签的 ZIP 可以下载后，再在 AstrBot 中检查更新。

插件源列表、版本号和 MD5 一起更新，避免命中旧的源缓存。发布内容只包含代码、说明和源索引；运行时配置保存在 AstrBot 的插件配置目录中。
